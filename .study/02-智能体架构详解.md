# 智能体架构详解

## 一、Agent 继承体系

JoyAgent-JDGenie 的智能体采用经典的面向对象继承设计，核心类图如下：

```
BaseAgent (抽象基类)
    │
    ├── ReActAgent (抽象类 - ReAct 模式)
    │       │
    │       ├── PlanningAgent (规划智能体)
    │       ├── ExecutorAgent (执行智能体)
    │       └── ReactImplAgent (ReAct 实现智能体)
    │
    └── SummaryAgent (总结智能体)
```

## 二、BaseAgent - 智能体基类

**源码位置**: [BaseAgent.java](../genie-backend/src/main/java/com/jd/genie/agent/agent/BaseAgent.java)

BaseAgent 是所有智能体的基类，定义了智能体的核心属性和通用行为。

### 核心属性

| 属性 | 类型 | 说明 |
|------|------|------|
| name | String | 智能体名称 |
| description | String | 智能体描述 |
| systemPrompt | String | 系统提示词 |
| nextStepPrompt | String | 下一步提示词 |
| availableTools | ToolCollection | 可用工具集合 |
| memory | Memory | 记忆（对话历史） |
| llm | LLM | 大语言模型调用器 |
| context | AgentContext | 上下文信息 |
| state | AgentState | 当前状态（IDLE/FINISHED/ERROR） |
| maxSteps | int | 最大执行步数 |
| currentStep | int | 当前步数 |

### 核心方法

```java
// 抽象方法 - 子类必须实现
public abstract String step();

// 运行主循环
public String run(String query) {
    setState(AgentState.IDLE);
    updateMemory(RoleType.USER, query, null);
    
    while (currentStep < maxSteps && state != AgentState.FINISHED) {
        currentStep++;
        String stepResult = step();
    }
    // 超过最大步数则终止
}

// 更新记忆
public void updateMemory(RoleType role, String content, String base64Image, Object... args);

// 执行单个工具
public String executeTool(ToolCall command);

// 并发执行多个工具
public Map<String, String> executeTools(List<ToolCall> commands);
```

### 运行机制

`run()` 方法是智能体的主循环，采用 **step-by-step** 的迭代模式：
1. 初始化状态为 IDLE
2. 将用户 query 加入记忆
3. 循环执行 `step()` 直到达到最大步数或状态变为 FINISHED
4. 每一步的结果被收集，最终返回最后一步的结果

## 三、ReActAgent - ReAct 模式抽象类

**源码位置**: [ReActAgent.java](../genie-backend/src/main/java/com/jd/genie/agent/agent/ReActAgent.java)

ReAct（Reasoning + Acting）模式是当前 Agent 领域最经典的设计模式之一，核心思想是**交替进行思考和行动**。

### 核心抽象方法

```java
// 思考过程 - 决定是否需要行动
public abstract boolean think();

// 执行行动
public abstract String act();
```

### step() 实现

```java
@Override
public String step() {
    boolean shouldAct = think();
    if (!shouldAct) {
        return "Thinking complete - no action needed";
    }
    return act();
}
```

### 数字员工（Digital Employee）

ReActAgent 还包含一个创新特性——**数字员工生成**：

```java
public void generateDigitalEmployee(String task) {
    // 1. 格式化系统提示词
    // 2. 调用 LLM 生成数字员工配置
    // 3. 解析 LLM 响应，更新工具集合
}
```

数字员工是根据当前任务动态生成的虚拟角色，为每个工具分配一个"人设"，使工具调用更加智能化。例如，`file_tool` 可能被分配为"市场洞察专员"，让 LLM 更自然地决定何时使用哪个工具。

## 四、PlanningAgent - 规划智能体

**源码位置**: [PlanningAgent.java](../genie-backend/src/main/java/com/jd/genie/agent/agent/PlanningAgent.java)

PlanningAgent 是 Plan & Solve 模式中的规划者，负责将用户任务拆解为可执行的子任务列表。

### think() - 规划思考

1. 获取文件信息，替换提示词中的占位符
2. 如果关闭了动态更新 Plan，直接执行下一个 task
3. 调用 LLM 的 `askTool()` 方法，携带 `PlanningTool` 作为可用工具
4. LLM 返回工具调用（通常是调用 `planning` 工具创建计划）
5. 将 LLM 响应加入记忆

### act() - 规划执行

1. 如果关闭动态更新，直接获取下一个任务
2. 执行 LLM 返回的工具调用（创建/更新计划）
3. 从 PlanningTool 中获取当前步骤的任务
4. 如果所有步骤完成，设置状态为 FINISHED
5. 返回当前步骤的任务描述（多个任务用 `<sep>` 分隔）

### PlanningTool

PlanningAgent 内置了一个特殊的工具——`PlanningTool`，它不是外部工具，而是用于管理任务计划：

- **create**: 创建任务计划
- **mark_step**: 标记步骤状态（not_started/in_progress/completed/blocked）
- **finish**: 标记任务完成

### 计划格式示例

```
["执行顺序1. 信息搜索: 搜索美元和黄金的最新走势数据", 
 "执行顺序2. 数据分析: 分析搜索到的数据并提取关键指标",
 "执行顺序3. 报告生成: 生成网页版走势分析报告"]
```

## 五、ExecutorAgent - 执行智能体

**源码位置**: [ExecutorAgent.java](../genie-backend/src/main/java/com/jd/genie/agent/agent/ExecutorAgent.java)

ExecutorAgent 是 Plan & Solve 模式中的执行者，负责执行 PlanningAgent 分配的每个子任务。

### think() - 执行思考

1. 获取文件信息
2. 调用 LLM 的 `askTool()` 方法，携带所有可用工具
3. LLM 决定调用哪些工具来完成当前子任务
4. 如果 LLM 没有返回工具调用，说明任务已完成

### act() - 执行行动

1. 如果没有工具调用，标记任务完成
2. **并发执行**多个工具调用（使用 CountDownLatch）
3. 将工具执行结果加入记忆
4. 对于特定工具（code_interpreter、report_tool 等），不发送 tool_result 事件

### 关键特性

- **数字员工生成**: 在 `run()` 开始时调用 `generateDigitalEmployee()`
- **并发工具执行**: 支持同时调用多个工具，提高效率
- **任务前缀**: 在用户任务前添加 `taskPrePrompt`，引导 LLM 聚焦当前子任务

## 六、ReactImplAgent - ReAct 模式实现

**源码位置**: [ReactImplAgent.java](../genie-backend/src/main/java/com/jd/genie/agent/agent/ReactImplAgent.java)

ReactImplAgent 是 ReAct 模式的具体实现，与 ExecutorAgent 类似但更简洁，直接面对用户的原始 query，不经过 PlanningAgent 拆解。

### 与 ExecutorAgent 的区别

| 特性 | ReactImplAgent | ExecutorAgent |
|------|---------------|---------------|
| 使用模式 | ReAct 独立模式 | Plan & Solve 模式中的执行者 |
| 任务来源 | 用户原始 query | PlanningAgent 分配的子任务 |
| 数字员工 | 支持 | 支持 |
| 并发工具执行 | 支持 | 支持 |
| 独立运行 | 是 | 否（需配合 PlanningAgent） |

## 七、SummaryAgent - 总结智能体

**源码位置**: [SummaryAgent.java](../genie-backend/src/main/java/com/jd/genie/agent/agent/SummaryAgent.java)

SummaryAgent 负责在任务执行完成后，对整个过程进行总结。

### 核心方法

```java
public TaskSummaryResult summaryTaskResult(List<Message> messages, String query) {
    // 1. 将所有消息格式化为历史记录
    // 2. 构建包含文件信息的系统提示词
    // 3. 调用 LLM 生成总结
    // 4. 解析 LLM 响应，提取总结和关联文件
}
```

### 总结格式

LLM 的响应格式为：`总结内容$$$关联文件名1、文件名2`

- `$$$` 前面是任务总结文本
- `$$$` 后面是关联的产出文件名列表

## 八、AgentContext - 智能体上下文

**源码位置**: [AgentContext.java](../genie-backend/src/main/java/com/jd/genie/agent/agent/AgentContext.java)

AgentContext 是贯穿整个请求生命周期的上下文对象：

```java
public class AgentContext {
    String requestId;          // 请求ID
    String sessionId;          // 会话ID
    String query;              // 用户原始查询
    String task;               // 当前子任务

    ToolCollection toolCollection;  // 工具集合

    Integer agentType;         // 智能体类型
    List<File> taskProductFiles;  // 当前任务产出文件
    String templateType;       // 模板类型
}
```

## 九、两种核心模式对比

### ReAct 模式

```
用户 Query → ReactImplAgent → [think → act] 循环 → SummaryAgent → 结果
```

- 适合简单任务
- 单个 Agent 直接处理
- 思考-行动-观察循环

### Plan & Solve 模式

```
用户 Query → PlanningAgent(拆解任务) → ExecutorAgent(执行子任务) → PlanningAgent(更新计划) → ... → SummaryAgent → 结果
```

- 适合复杂任务
- 规划和执行分离
- 支持子任务并发执行
- 支持动态更新计划
